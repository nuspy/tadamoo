# TaDaMoo for Linux, complete, 2.3 (victory-lap)

The harness (server and web page), the installer, the Basalt-Plus engine built for Linux x86_64 with its CUDA 13 libraries, agent-desktop and agent-browser, in one archive, built together in one run.

- **File:** `TaDaMoo-linux-complete-v2.3.tar.gz` (500 MB).
- **SHA-256:** `7bd00fa12f8bca798795308aecd286593cdd05902a41e961b5bc26e0053bb8b0`
- **Needs:** Linux x86_64 with systemd, Python 3.10 or newer with `venv` and `pip`. The engine needs an NVIDIA Blackwell GPU.
- **Install:** `tar xzf` the archive, then `sudo deploy/linux/install.sh install --components harness,basalt --public-name NAME --proxy nginx --generate-key [--remote-admin]`. Strata is fetched from its own release with `--strata-download`.

## New in 2.3 (victory-lap)

2.3 replaces 2.2: it fixes the two bugs that stopped 2.2 from starting for some people, and brings the work done since.

- **Fixes to 2.2.** A model file written on Windows (line ends `\r\n` in the tokenizer's merges) loads again (the server failed with "merge 0 names a token outside the vocabulary"). The Loader's Load works again after the import (it failed with "unexpected keyword argument 'vision'"). Dictation recovers from a CUDA error in its helper (the helper is started again and the request tried once more; before, every later dictation failed). `voice.json` is written through its own temporary file and read again when Windows refuses it for a moment (two writers could leave it empty or fail with Errno 13). The commit checks count the page file's maximum, not the size it has now (a dynamic page file grows on demand).
- **VRAM, used fully.** At load the engine reads the free VRAM again until it settles and a cache that comes up short loses only what is missing; a start short of VRAM leaves the cache's tail unmapped and the engine maps it back between requests as VRAM frees, once the room has lasted 45 seconds (so a voice function that unloads and loads again finds its VRAM free). A voice function that cannot be lent VRAM because the Windows commit has no room says so instead of showing the figures of a model reload.
- **Monitor > VRAM Explorer.** A page with every process using the GPU (gputaskman's collector, MIT) and a chart of VRAM over time, total or by process, with a day of history.
- **The layer loop (experimental, off by default).** `--layer-loop A:B:K --layer-loop-alpha a1,...,aK` runs a window of layers K times with weights and experts shared and state per pass. With the flag off nothing changes; with alpha `1,0` or `0,1` the answers equal the model without the loop. Measured without training on wikitext-2 it gives no gain: the least damage is in layers 8 to 16 (see `docs/configuration/layer-loop.md` and `docs/precision/features.md`).
- **The quality gate writes its own base.** `ppl_gate.py --write-base --text FILE` writes the gate's reference with the engine itself, and the report gives the paired error of `ln(PPL/base)` over the chunks.
- **Still missing, and not working yet**: telephony (calls through a real phone) and the USB device with its model.
