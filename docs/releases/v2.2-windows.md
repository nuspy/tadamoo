# TaDaMoo for Windows, 2.2 (victory-lap)

The full setup: the Basalt-Plus engine, the harness (server and web page), the desktop app, agent-desktop and agent-browser, and everything they need on one PC.

- **File:** `TaDaMoo-Windows-v2.2-setup.exe` (728 MB).
- **SHA-256:** `b67cbbced8757096507a306931359ffe78c6cef03ba797664a3994f18b87c272`
- **Needs:** Windows 10 or 11 x64. For the engine, an NVIDIA Blackwell GPU (RTX 50 series) and its driver; without it the harness runs through the providers.
- **Install:** run the setup, then `TaDaMoo.exe`. agent-desktop is not signed: SmartScreen or an antivirus may warn, and the built-in backend is the fallback. The setup offers the TaDaMoo command line and, if asked, the two Windows Terminal profiles.

## New in 2.2 (victory-lap)

- **The original Basalt 0.5.6 inside**: the engine, build and tools of the original Basalt v0.5.6 (parallel batching on every model among them), with ours put back on top: the LoRA fusion, the IQ quantizers, the VRAM arbiter, the Windows commit give-back, the Qwen3.6 engine and the projector choice. The Python server follows 0.5.6's layer; the web page and the harness are ours.
- **One configuration format**: only version 2 (`version: 2`, a `models` list, an `engine` block shared by the models, a `server` block). The old-format tool and its pointer are gone; the model file is checked before anything loads, and a stored profile that has `answer-room` as a switch is read as the number it means.
- **Documents, on a copy**: Word, Excel, PowerPoint and PDF files are read and changed (headers, footers, footnotes, endnotes and text boxes of a Word file too). The editing tools never write the original: the result is a copy (`name.edited.ext`) offered as a link in the chat. `ask_document` puts a file in front of the model, `query_attachment` runs SQL over the tables of an attachment, a PDF is read from its text layer and a scan says so.
- **A shorter prompt, on by default**: the rare tools are listed with one line and the skeleton of their parameters, and the model asks `tool_help` for the rest before it uses one. Measured on the real model (k = 5, 600 W): 70 of 70 tasks passed with it and without it, the prompt read 29% shorter on ordinary tasks and 11% on the document tasks (one more step when a rare tool is needed). Settings > General > Inference settings has the switch; Settings > Skills has HotLoad / ColdLoad on every skill.
- **Skills in plans**: a plan step can carry skills of its own (only for that step) and the plan can carry skills for every step (given whether the step uses them or not). The instructions arrive when the step starts.
- **Instruction files in cascade**: an `AGENTS.md` for each project, applied after the person's own and each folder down to the working folder; the technical session removes the concepts that repeat.
- **The command line**: *TaDaMoo CLI* profiles (PowerShell 7 and Windows PowerShell) with the TDM icon in the menu of Windows Terminal, the Windows PowerShell one as its default; the module of API-CLI puts the harness in the terminal with the `§` prefix and the `tadamoo` command (its test in a real console is still to be done).
- **Turn off and Restart under the Windows service**: a clean exit stays stopped, a crash starts the server again, and a restart exits with a code the service takes as a reason to start it (`docs/windows-service.md`).
- **Models > Usage**: the tokens of every model call, by provider.
- **Fixes**: a body that does not arrive is a 408, a pending VRAM resize is a 202, the Responses stream closes its generators on a broken pipe, the launchers read the model from the version 2 file, a 1 TiB image read, a Windows file URL name; the 81 Python test files that failed after the import are repaired.
- **Still missing, and not working yet**: telephony (calls through a real phone) and the USB device with its model.
