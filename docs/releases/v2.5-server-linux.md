# TaDaMoo server for Linux, 2.5 (victory-lap)

The harness, the installer, agent-desktop and agent-browser, with no engine: for a server that answers through the providers. It is the complete archive without `engines/basalt`.

- **File:** `TaDaMoo-server-linux-v2.5.tar.gz` (30 MB).
- **SHA-256:** `a85682f13f4458b24ad2e8ad5bf363657ee368de4c5f368cba164bf9f2dba1dc`
- **Needs:** Linux with systemd, Python 3.10 or newer with `venv` and `pip`.
- **Install:** `tar xzf` the archive, then `sudo deploy/linux/install.sh install --public-name NAME --proxy nginx --generate-key [--remote-admin]`.

## New in 2.5 (victory-lap)

2.5 follows 2.4 with the work done on long answers, the file tools and the end of a turn.

- **One number for the size of a long text.** The capacity of a reply (its length in tokens, written by hand for the model or the provider, else measured, else 10,000) times the words a token makes gives the words one reply holds. The part of a long text, the least a part is planned at, the most parts, the continuations, the output cap of a part, the plan prompt, the pieces of the check and the default length all come from it; the fixed sizes are gone.
- **The words a token makes belong to the conversation.** Settings > Inference has a "Words per token (%)" field, with an "i" that lists typical values by language; empty is 60. It is no longer a field of the model's record or the provider's form.
- **A length you give is an order of magnitude.** A text from 0.8 to 1.25 times it is right; nothing is added or rewritten to move it inside that band. Write that the length is exact and the band is 0.97 to 1.03. The harness texts say it too.
- **The older steps are folded when an answer is final.** If nothing waits and the context is over its threshold, the compaction runs at once, while you read, and the next request does not wait for it.
- **A very long final answer is also kept as a file.** From a quarter of the capacity in words, the answer is saved as a file you can save, and its link is added at its end.
- **File tools by blocks.** `read_file` gives the map of a file, a section by its title or a range of words; `edit_file` replaces, deletes, inserts beside or moves a block by its lines (with the version) or its section; `write_file` and `edit_file` copy a text from your last reply or from a file with `source`, so a text that exists is never typed again. The tool list grows by about 550 tokens: the cache of a conversation already open is rebuilt at its first request.
- **From the end of 2.4.** Links to the files handed over are clickable in a reply; the check that a job is done reads only the new request; the mission card names the files made and the last commands.
- **Still missing, and not working yet**: telephony (calls through a real phone) and the USB device with its model.

(This package has no engine: the items about the engine apply to the packages that have one.)
