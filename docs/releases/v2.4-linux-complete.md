# TaDaMoo for Linux, complete, 2.4 (victory-lap)

The harness (server and web page), the installer, the Basalt-Plus engine built for Linux x86_64 with its CUDA 13 libraries, agent-desktop and agent-browser, in one archive, built together in one run.

- **File:** `TaDaMoo-linux-complete-v2.4.tar.gz` (500 MB).
- **SHA-256:** `e54a9c0a726f2b3f39088c11f3e618e8e224f15302e60fdf916c0ee5653ff70d`
- **Needs:** Linux x86_64 with systemd, Python 3.10 or newer with `venv` and `pip`. The engine needs an NVIDIA Blackwell GPU.
- **Install:** `tar xzf` the archive, then `sudo deploy/linux/install.sh install --components harness,basalt --public-name NAME --proxy nginx --generate-key [--remote-admin]`. Strata is fetched from its own release with `--strata-download`.

## New in 2.4 (victory-lap)

2.4 follows 2.3 with the work done on the providers, the context and the long answers.

- **Providers in an order you set.** On Models > Providers, drag a card or use its arrows. The order of the list is the order the providers are tried in when the chosen route does not answer: the chosen route, the loaded model, then the other providers in that order, each only if the function's usual rules allow it (consent, cap). An error of one sends the call to the next, until none is left; the error raised is the first real one. A function pointed at a model on this PC by name keeps its single route.
- **The context follows the route a call takes.** The harness reads the window of the provider a call goes to now (the one in that provider's record; none when the record has none, no longer the loaded model's), and asks again every 30 seconds while a request runs, so a model loaded after the request began, or a route that changed, is followed instead of the 32k that was assumed. Put the context window and the output limit of each provider in its record.
- **The compaction summary has room.** Its answer limit goes from 1,500 to 3,000 tokens: a summary that ran past 1,500 was cut and replaced by the mechanical extract.
- **Long answers.** A text asked above 10,000 answer tokens (about 6,000 words in Italian) is written in parts, instead of 3,000; a measured length of the model can only lower that number. Italian words are counted at 1.6 tokens. On the local engine a report of up to 6,000 words comes out in one reply.
- **The settings page of the Android app.** The gear icon of the chat opens the inference settings again: the app puts the key in a cookie and the listener for phones reads it for the page and its own files only, so the 401 "missing or wrong API key" is gone. Every API call still needs the key in its header. The server and the app must both be 2.4.
- **Still missing, and not working yet**: telephony (calls through a real phone) and the USB device with its model.
